## Data flow and field interpretation

The caller owns a24-byte **selection descriptor** in its local stack frame. It is not the24-byte **aura record**. The shared helper initially reads identity words atdescriptor+0/+4 and selection fields at+8/+0C/+10 with a mask byte at+14; native lookup chooses the record subsequently. The descriptor must not be confused with the later record whose Duration/EndTime fields also have offsets0x10/0x14.

After the resident-unit path resolves an aura record, the instruction stream reads duration fromrecord+0x10, tests it with signedJLE, and reads expiry fromrecord+0x14. Nonpositive duration emits zero duration/expiry; positive duration and unsigned expiry are scaled into the ordinary API outputs. This corroborated the one-expression timer repair already hosted-verified at67632376. It does not justify changing every aura flag or claiming a uniform effective-magnitude field.

The complete ordinary path writes eleven Lua results. The separately observed fallback searches a bounded64-entry representation and emits reduced information, including zero duration/expiry and nil caster on that path. Those zeros therefore require their path/context interpretation; ordinary API fallback zeros are not automatically proof of a resident permanent aura. No production fallback reinterpretation was added by the timer repair.

## Lifetime and invalidation

**Native selection descriptor:** caller-local storage exists only for the wrapper invocation. No ownership transfer, persistent allocation or valid post-return pointer is established. Never retain its address across calls or waits.

**Native resolved unit/aura data:** the helper obtains current lookup results and reads fields for the result construction. It does not return the record pointer as the result count. Unit disappearance, roster/object replacement, aura application/removal, expiration and frame changes invalidate assumptions about a later lookup. This analysis does not establish an atomic full-frame snapshot, ABA protection or safe concurrent mutation of all consulted tables.

**Managed aura snapshot:** `WoWUnit.GetAllAuras` creates a managed AuraInfo array and constructs WoWAura instances by value; `_data` is readonly. The timer subsequently combines copied Duration/EndTime with the observed clock. Retaining the managed object does not keep its native record alive or refresh caster, flags, stack data or external magnitude. The selecting-caster/recipient ownership guards remain separate from this snapshot's content validity.

## Executor and thread requirements

For registered Lua API queries, the actual host `Lua.GetReturnValuesCore` requires a present executor, memory object and nonzero currently read Lua-state pointer. It holds **executor.AssemblyLock** through shared return-buffer initialization, assembly construction, execution and result-string conversion. It restores the Lua stack after the request and reads the result buffer with the existing cache-disabled scope. There is no separately observed return-buffer lock or BeginExecute call inside this method; neither is invented here.

This is the existing managed serialization/dispatch contract, not proof that the analyzed functions are independently reentrant or safe from arbitrary native threads. The native API expects a valid state and normal client object/Lua context. Scheduling onto the actual client executor, frame lifetime and concurrent native mutation require their own retained executor evidence and supervised acceptance. This addendum introduces no direct native entrypoint invocation and does not alter the executor or its locks.

The managed `GetAllAuras` path reads memory rather than directly calling UnitAura. Its header reads follow the existing Memory cache, while its pointer bulk read is uncached; its own read-validity repair must preserve that distinction. The native API is semantic corroboration of record fields, not evidence that all managed collection data arrived through the API stack.

## Read versus mutation

All **tools used here** were read/analysis-only. The **analyzed function when invoked** is not a side-effect-free byte reader: it pushes strings/numbers/nil values onto the Lua result stack and invokes lookup helpers. No gameplay action is added or executed by this analysis, but a complete absence of internal cache/lookup side effects across every callee is not certified. Query result construction, IDA database mutation and game-state mutation are distinct categories.
