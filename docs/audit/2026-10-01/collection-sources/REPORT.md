# Carry selected item sources into the actual collection behavior

Wholesome placed creature IDs on generated order nodes, but the real collection behavior reads its sources from the quest definition. Creature hints were missing there, and repeated same-item definitions could hide all but the first source. The builder now writes typed creature hints into CollectFrom and merges selected same-quest, same-item, same-count alternatives and their locations. Other items, auxiliary requirements, unselected sources and conflicting quantities are not silently combined.

The actual collection source predicate also required optional creature query metadata before consulting an explicit profile hint. It now recognizes the explicit source without that optional cache, while requiring an enabled Unit object and matching nonzero object/descriptor GUIDs. Null/zero/player/invalidated objects are rejected, including after source memoization. Undeclared sources retain the existing cache/database fallback. Combat eligibility, loot permission, item counts and completion remain separate authorities; no new native dispatch is added.

An optional source-bound CollectionRouteRepairs schema is implemented and tested. It can replace an unproved ordinary final-item target or append a proven alternative without discarding an old valid source. It validates expected original row/type/item/count/index, unique ownership, source identity, existing count/object repairs, navigation vetoes and bounded nonconflicting indices. The source exporter only proposes positive, ungrouped, nonconditional, nonscripted ordinary loot with source-matched default geometry and giver-map anchors. It preserves auxiliary objectives and all existing knowledge.
