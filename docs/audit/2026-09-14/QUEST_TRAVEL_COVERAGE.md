## What exists and what remains

**Not an entirely 2D bot.** Standard pickup and turn-in use full WoWPoint coordinates through ActionMoveToPoi -> Flightor -> Navigator. Scheduler endpoint probes use XYZ and an assessment cache keyed by Map/X/Y/Z; safety vetoes remain per hotspot. Native route points, vertical arrival checks and downhill lookahead already consider elevation. But QuestSchedulerSnapshot's location and candidate Distance function use X/Y, so coarse scan/ranking is still planar. Do not blindly replace all Distance2D calls: safety, reachability and actual route cost need distinct tests; some planar filters are intentional.

**Wind riders are considered for standard pickup and turn-in ground travel.** Both forced behaviors reach the same shared chain; no blanket pickup-disable branch was found. Navigator's automatic taxi check runs only at DistanceSqr>160000 (>400 yards). FlightPaths.ShouldTakeFlightpath additionally checks UseFlightPaths, active reason and a shared15-second cooldown. When ground travel is valid it requires an absolute time difference>30seconds and a faster taxi estimate. Thus it is not unconditional coverage for every quest/custom behavior. A destination close in straight-line distance but far by terrain detour can miss this entry; quest-target changes inside the cooldown can delay reconsideration. These are source-supported hypotheses for investigation, not a diagnosed cause of this user's observation.

**Taxi routing is not globally optimal.** FindClosestFlightNodes chooses the nearest same-continent cached origin, then the nearest destination among that origin's named connections. It does not compare all reachable origins/endpoints. Ground approach/last-mile lengths use3D; airborne time is a2D approximation. Test a disconnected nearest origin with a usable alternate, unsafe approach, missing/partial mesh, stale cache, route changes, zero/invalid speed and ties before repair.

**Setup/cleanup require real-owner tests.** SetFlightPathUsage assigns from/to before validation and tests startNode?.MasterEntry!=0U; nullable inequality can be problematic for a missing origin, while normal ShouldTakeFlightpath prechecks nodes. SetPoi's Use branch requires a non-null argument. Neither proves the live symptom. QuestBot's vendor/service tree normally precedes quest execution; LevelBot handles Fly POIs; BotPoi.Clear calls FlightPaths.Reset. This is counterevidence to blanket claims that pickup always overwrites Fly or flight state never resets. Trace direct POI replacement, failed interaction, frame absence, selection rejection, insufficient gold, combat/cancellation and confirmed landing.

**Lifts have substantial safeguards but incomplete route coverage.** MeshNavigator proves source/destination mesh landings and safe corridors, retains onward-route metadata, uses XYZ and checks ground support. ElevatorTransitController binds the actual transport identity, confirms attachment and stable docking and requires safe exit evidence. Destination changes/Clear cancel transit. Preserve these guards. The nearby-lift heuristic requires vertical gap>=12, player-target planar<=120, player-lift<=35, target-lift<=70 and platform Z within the floor band. It can miss farther lifts or a platform at another shaft phase. The inspected controller/handler has no overall elapsed-time budget; other owners may cancel, so do not claim whole-bot infinite waiting without tracing them. ProfileBuilder's explicit Freewind/Great Lift guards cover objective/ancestor paths, not identical pickup/turn-in XML guards; generic lift navigation still exists for those phases.

Existing managed lift suites pass atc237ca5b, including continuity28/28, intermediate veto8/8, retained original5 plus new6 scenarios, route continuation17/17 and terminal ownership18/18 in the combined run. Those are inherited tests, not new live acceptance of every route or of the reported symptom.

## Required next test-first slices

1. **Actual pickup/turn-in parity:** hold settings, character, origin/destination, cache, time and service tree constant; vary only quest phase. Cover below/at/above400yards, cooldown/target change, disabled taxi, no/disconnected nodes, usable alternate origin, frame absence/selection failure/gold, in-flight/arrival, combat/death/cancel and map changes. Add decision/rejection evidence at actual owners, not a helper that restates desired behavior; retain successful taxi and ordinary walking controls.
2. **Elevation-aware selection/cost:** sameXY/differentZ, reachable ramp versus cliff, bridge/cave/building floors, unsafe/partial/missing mesh, path-probe budget, lift approach/wait/ride/exit versus ground/taxi last-mile cost. Unknown route evidence must remain unknown, not safe. Extend snapshots/provenance only with reproduced owner evidence; do not equate Euclidean3D distance with a safe route.
3. **Lift lifecycle and graceful failure:** farther safe lift, platform phase/disappearance/wrong identity, missed boarding, falling/lost support, interrupted docking/exit, inaccessible landing/onward-route loss, new quest/destination, stop/restart, delayed observations and disconnect. Specify finite wait/retry budgets, explicit reason and safe stop/replan; never a blind walk-off escape. Test the full handler and controller, preserving successful ascent/descent controls.

These are open requirements, not completed tests. Inventory custom quest behaviors, boats/portals and other transport owners separately before any all-routes claim. Full W42, native/live acceptance and independent review remain open.
