# Release review: continuous travel and source-bound quest execution

The candidate is the existing PR99 branch. Its initial commit300d811b and failed receipts are retained. The resumed work resolves the observed integration failures and adds the seven runtime admission cases described in REPORT.md.

## Reviewed invariants

Continuous flight consumes reached native queue points and prepares safe local successors before the current endpoint. No intermediate endpoint grants landing or mount-removal authority. Unavailable future geometry retains only the independently validated current endpoint. A replaced journey, player, selected object, profile or native owner cannot use its predecessor's request.

Same-NPC movement retains semantic work identity while each submitted route still has exact current destination admission. Pickup cleanup is reference-owned and recursively retires conditional work without clearing a successor's POI. Optional travel-cost estimation is not a stop authority; actual mount preparation and final interaction remain separate.

The Arelion handler's frame preparation no longer depends on hidden stale metadata. Item use is bound to current parent acceptance/progress, exact living recipient, observed ground-ready endpoint, carried GUID/slot, selected target and client request lease. A missing or stale raw quest snapshot is not an unfinished quest. Prepared-command admission performs pure identity/raw-memory checks, not nested Lua or native geometry queries.

The source audit has4335 unique quest members and5771 effective objective rows with exclusive accounting. Scheduling and materialization use the same mechanism policy. The603 quests with unresolved handler/source requirements remain explicit holds, not alleged complete implementations. The catalog is an admission reference, not a live action receipt.

## Evidence limits

Controlled Lua5.1, raw observations and complete adapter tests establish reproducible command admission and acknowledgement behavior. Native mesh replay establishes retained-engine geometry results, not physical traversal. Neither establishes that the user's realm has identical scripts. Live post-update acceptance remains a separate observation; the repair must not launch or stop that run.

No reviewer subagent was used. Release requires clean-source local and hosted gates, exact merge/source verification, and a staged idle-installation replacement with rollback and protected-data comparison.
